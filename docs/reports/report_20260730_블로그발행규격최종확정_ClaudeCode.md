## 1. 배경

SVIL Ghost 블로그의 섹션 수·이미지 수 규격이 세션·문서마다 달라 충돌하고 있었다. 실제로 남아 있던 숫자는 다음과 같이 6종 이상이었다.

- 6섹션 / 12섹션 / 20섹션 / 32~37섹션
- 4섹션당 이미지 1장 / "정확히 5장" / 6장 / 8장

여기에 ComfyUI가 세션 시작 시 반복적으로 오프라인이 되는 문제(한 세션에서 4회 다운 기록)와, 작업 후 서버를 켜둔 채 떠나 VRAM을 점유하는 문제가 겹쳐 있었다. InBlue가 두 사안을 한 번에 확정 지시했다.

## 2. 확정된 규격

| 항목 | 최종 값 |
|---|---|
| 섹션 수 | **최소 24섹션(h2), 상한 없음.** 주제가 요구하면 40·50섹션도 좋다 |
| 이미지 | **2섹션당 1장** (24섹션=12장 / 30섹션=15장 / 36섹션=18장 / 40섹션=20장). 대표이미지 포함 계산 |
| 이미지 근거 | **영상 제작 때 그대로 재사용된다.** 이미지 1장 = 영상 장면 1개 → 임의 감축 금지 |
| 일일 발행 수 | 최대 3건 (기존 유지, 변경 없음) |

**분량 판단 순서** — 거꾸로 하지 않는다.

1. 주제에 반드시 들어가야 할 내용을 먼저 다 나열한다.
2. 필요한 섹션 수를 결과로 얻는다.
3. 24 미만이면 리서치가 부족한 것이니 더 조사한다.
4. 40·50이면 그대로 간다. 줄이지 않는다.

섹션 수를 맞추려고 내용을 압축·누락하거나, 채우려고 부풀리는 것을 모두 금지했다.

### ComfyUI 생애주기 3원칙

1. **시작** — `svil_status`로 확인해 `online=false`면 `svil_start_service("comfyui")`, `online=true` 재확인(20~60초) 후 첫 생성. 사용자에게 실행을 요청하지 않는다.
2. **경합** — `svil_queue_status`/`svil_gpu_status`로 다른 세션 점유 확인 시 기다리지 않고 `[이미지 홀더]` 표시 후 `published` 그대로 발행. 후속 채움을 장수 명시해 별도 기록.
3. **종료** — 전량 생성·업로드·asset 등록 완료 후 `svil_stop_service("comfyui")`. 다른 세션이 이어 쓸 예정이면 예외(내가 올린 것만 내린다).

플레이스홀더 문자열은 **`[이미지 홀더]`로 통일**. 과거 글에 구 문자열 `[이미지 추후 생성]`이 남아 있으므로 후속 채움 시 두 문자열을 모두 검색한다.
