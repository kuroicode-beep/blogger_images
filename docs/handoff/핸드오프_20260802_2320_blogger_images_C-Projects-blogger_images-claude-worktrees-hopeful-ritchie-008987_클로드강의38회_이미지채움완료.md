## 다음 세션이 알아야 할 것

### 1. 컨텍스트 절약이 이 작업의 핵심 제약이었다

포스트 본문이 회당 60~90KB다. 그대로 컨텍스트에 올리면 몇 회차 못 가서 막힌다.

- `ghost_get_post` 결과는 tool-results 파일로 자동 저장된다. **본문을 Read하지 않는다.**
- 구조만 파이썬으로 뽑아 쓴다 — `scan.py`(플레이스홀더별 직전 h2) / `layout.py`(h2별 이미지 유무).
- 본문이 컨텍스트에 들어오는 건 **발행 직전 1회뿐**이다(`ghost_update_post`에 html을 넘겨야 하므로 불가피).
- **전수 감사는 `sitemap-posts.xml` → curl이 압도적으로 싸다.** MCP를 38번 부르는 것과 비교가 안 된다.

### 2. 이미지 검수는 컨택트시트로

ffmpeg `xstack`/`tile`로 한 회차 전량을 한 장에 합쳐 Read 한 번으로 본다.
개별 확인 대비 반려 검출률이 크게 높다(실측: 개별 16회 → 2건 적발 / 컨택트시트 1장 → 6건 적발).

### 3. Z-Image는 negative prompt가 무시된다

cfg 1.0 고정이라 `neg_prompt`가 물리적으로 반영되지 않는다.
**"~하지 마라"가 아니라 어휘 자체를 바꿔야** 회피된다. 부정형은 오히려 그 개념을 소환한다.

이번에 새로 확인한 함정:

| 단어 | 나온 것 | 대체어 |
|---|---|---|
| `branches` | 검은 나뭇가지 | `straight slender rods` |
| `splitting into two` | 가시 달린 번개 | `divides into two straight strips` |
| `in order from smallest to largest` | 막대그래프 | `slotted into its own groove` |

누적 함정표는 `C:\youtube\docs\가이드_20260731_블로그이미지규칙_ClaudeCode.md`에 있다.
(기존: `plate`→접시, `marker`→마커펜, `shape`→실사 사람 손, `key`→실사 열쇠,
`question`→물음표 글자, `tablet`→알약, `sign`→영문 안내판)

### 4. 동시 집필은 중복 발행을 못 잡는다

4·5회차가 중복 발행됐던 원인이다. 중복 확인은 **발행 직전 `ghost_list_posts` 한 번뿐**이라
두 세션이 동시에 집필 중이면 서로를 볼 수 없다.

→ **긴 시리즈 작업은 착수 시점에 Outline에 "N회차 집필 착수"를 먼저 남긴다.**

이번에 InBlue 지시로 플레이스홀더판 2건을 삭제하고 이미지 보유판을 남겼으며,
삭제분의 부제 포함 제목을 유지분에 이관했다.
(**제목만 갱신하면 본문·슬러그가 보존된다** — 검증 완료.)
